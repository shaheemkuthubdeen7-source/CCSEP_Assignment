Feature & Vulnerability Details

Aadhil's Design Notes

Intended Data Flow

Client issues POST /api/auth/login with JSON body. The backend passes credentials to User.findOne() in MongoDB to locate matching account records.

The Insecure Code Path

routes/auth.js:44 NoSQL Query Injection 
// INSECURE: Accepts unvalidated input directly into Mongoose query
const queryFilter = {
  username: req.body.username,
  password: req.body.password  <-- Unchecked object injection
};
const user = await User.findOne(queryFilter);

Why Input Handling is Unsafe

When Express parses application/json, nested objects like {"$ne": ""} are passed into Mongoose as query operators instead of literal strings. This allows an attacker to evaluate the query to true without supplying the actual password.

Boundary & Traversal Architecture

Aadhil's Design Notes

Intended Directory Boundary

The service is intended to restrict file access exclusively to:
<project_root>/public/documents/

The Insecure Code Path

routes/documents.js:54 Path Resolution Vulnerability 
// INSECURE: Naive path.join without directory boundary enforcement
const baseDir = path.join(__dirname, '../public/documents');
const targetPath = path.join(baseDir, req.query.file); <-- Resolves ../
fs.readFile(targetPath, 'utf8', (err, data) => { ... });

Why Path Handling Fails

path.join() resolves .. segments relative to the base directory, but does not verify that the resulting canonical path remains within baseDir. Consequently, an attacker can traverse out of the folder to access simulated secrets at ../../config/.env.secrets.
